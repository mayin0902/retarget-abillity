# 规则评分、视觉 Agent 与人工校准

当前所有可变评分范围、权重、Rule 排名、覆盖门禁和 Agent Skill 由
[`strategies/movie60/<version>`](../strategies/movie60) 冻结。具体版本切换、A/B/C/D 范围修改和
Run 内快照见 [StrategyBundle 版本指南](STRATEGY_BUNDLES.md)。本文件解释指标语义，不再作为
可执行阈值的唯一事实源。

## 1. 三层结论不能混用

| 层 | 回答的问题 | 是否人工金标准 |
| --- | --- | --- |
| 自动 Quality | OCR、主体、结构、几何等可测指标保留得怎样 | 否 |
| 视觉 Agent | 与原图相比是否语义完整、自然、可用 | 否 |
| 项目人员 A/B/C/D | 是否符合真实上传标准 | 是 |

Rule使用第一层排序；Agent必须读取Rule证据并查看原图/候选高清图，但不能直接照抄Quality。最终
阈值和Skill只能由Calibration人工标签校准。

## 2. 自动 Quality（0–100）

```text
Quality = 100 × weighted_mean(
  Content Fidelity × 0.50,
  Visual Integrity × 0.30,
  Composition × 0.20
)
```

### Content Fidelity

| 证据 | 权重 | 含义 |
| --- | ---: | --- |
| ORB内容相似 | 0.25 | 局部特征能否在候选中找到 |
| OCR综合 | 0.35 | 字符召回0.65 + 序列相似0.35 |
| 人脸计数保留 | 0.20 | 源图有人脸时参与 |
| 人物计数保留 | 0.20 | 源图有人物时参与 |
| 商品计数保留 | 0.20 | 源图有商品时参与 |
| Logo候选计数保留 | 0.10 | 工程候选区，不是法律商标识别 |
| 目标类别F1 | 0.20 | 候选重检类别与源图对齐 |

缺失或不适用的指标不填0，而是在已观测指标上重新归一化，并同时报告 `observed_count`。

### Visual Integrity

清晰度保留0.25、边缘密度0.20、颜色直方图0.15、结构线0.20、变换安全0.20。

- Direct Warp：惩罚宽高各向异性；
- Crop：惩罚被切除的must-keep区域；
- Seam/Seam Full/Seam+Scale：惩罚接缝保护命中、局部扭曲和剩余全局拉伸；
- Mesh/Mesh Full：惩罚网格各向异性，三角形fold-over为硬失败。

### Composition

重要区域离边界的安全程度占0.60，梯度视觉重心平衡占0.40。

### Proxy等级

- 当前严格Movie60口径：A≥90、B≥72，其余C；
- 关键文字召回、显著人脸、空白、尺寸、fold-over等可触发硬门禁；
- Direct Warp另受确定性拉伸上限约束；
- Proxy A/B/C不是人工A/B/C/D。

## 3. Rule Selector

Rule不调用模型。它先应用生成状态和硬门禁，再按Quality、保护退化和确定性风险输出七候选完整
排名。每个Task都必须产生Decision，困难图不能通过跳过来抬高成功率。

Rule的优势是可复现、便宜、不会被提示词波动影响；局限是OCR/检测器可能误判，连续分也不一定
反映肉眼美观程度。因此Rule Top1必须进入高清复核，不能只凭分数直接称为A。

## 4. 视觉 Agent

### 输入

每个Task单独调用，不把60张图塞进一个上下文。输入包括：

- 保持原始宽高比的原图；
- 七张候选，别名固定为 `C0…C6`，显示method ID；
- 完整Rule排名、Rule Top1和每候选Quality/保护指标；
- 七候选总览；
- Rule Top1与Agent challenger的高清整图和关键局部；
- 固定结构化响应Schema和版本化Skill。

后续新运行使用 `agent_skills/qwen4-selector/v7/skill.yaml`；当前已完成的Movie60实验冻结于
Rule锚定v6，不能用v7名称改写历史结果。

### 判断优先级

1. 主体、脸、身体、商品、Logo是否自然且完整；
2. 简体中文标题、价格、日期和关键数字是否可读；
3. 是否存在全局拉伸、Seam局部扭曲、Mesh弯曲或Crop关键内容缺失；
4. 构图、留白和视觉层级是否仍像可直接使用的成图；
5. 前四项接近时，再用Quality与资源成本破同分。

`UNSAFE`只是风险证据，不是等级上限；`SUCCESS`也不是视觉通过。目标画布变化、合理重新排版和
元素缩放本身不扣分。检测器与清晰完整图冲突时，应记录矛盾并交给人工，不得只凭计数判C。

### Rule锚定覆盖门禁

1. Agent先看到完整Rule排名并提出challenger；
2. Rule Top1强制高清复核；不同challenger也必须高清复核；
3. 海报、多人、商品/Logo图增加文字框、人物框和主体框局部；
4. `core_content_preserved=false`、关键文字召回下降或主体数量下降时，不得推翻可用Rule A/B；
5. 只有配对视觉证据明确、无矛盾且等级更好时才能覆盖；
6. Schema非法、超时、证据矛盾或覆盖条件不足时fail closed回退Rule。

## 5. AIGC Gate

只有传统候选均存在实质问题，且素材允许第三方API外发、预算充足、幂等键未执行时，才允许每Task
单次生成。报告必须同时给出：

- 计划调用分母；
- 技术回图率；
- 成功图A/B率；
- 全计划分母A/B率；
- 成本区间和每个可用结果成本；
- 超时/服务错误后是否可能已经计费。

AIGC是语义重构，不能把原图检测框按相同坐标直接套到生成图；应在候选自身重新检测，并由高清
完整图确认文字、人物、Logo和结构。

## 6. 人工 A/B/C/D

- A：可直接使用；允许合理裁切、留白变化、缩放和重新排版；
- B：有轻微可见问题，但仍可上传或只需小修；
- C：关键内容或视觉自然度有实质问题，需要明显返工；
- D：严重缺失、错字、身份变化、大面积形变或技术损坏；
- A+B统计为通过。

人工理由要说明“哪里有问题、是否影响上传、为何给该等级”，不能只写“机器分低”。

## 7. 人机校准

### 人工等级不同

只对A>B、A>C、A>D、B>C、B>D、C>D的候选对统计机器排序正确率。

### 人工同等级

同级不要求机器同分，也不进入排序正确/错误。分别统计A=A、B=B、C=C、D=D的pair数、机器
分差中位数和P90。

### 全同级与并列最佳

- 一个Task全部同级时，不进入Top1命中率；
- 另报该Task机器最高分减最低分，并汇总中位数/P90；
- 多个候选并列人工最佳时，机器Top1命中任意一个均算命中。

Calibration20可用于更新规则和Skill；版本冻结后，Validation40只运行一次，不能反向调参。
