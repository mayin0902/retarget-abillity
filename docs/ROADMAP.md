# 路线图

## P0：完成人工闭环（当前）

- 在 `movie60-review` 中完成60个任务、420个候选逐张评分；
- Calibration20先评，记录等级、六项细分、问题类型和自由理由；
- 只根据Calibration反馈调整评分器和Agent Skill，生成不覆盖v1的v2；
- 冻结v2后对Validation40运行一次；
- 输出等级分数区间、异级排序正确率、同级分差和并列Top1命中率；
- Git只提交代码、测试、配置、当前文档和无像素数据合同。

## P1：评分与 Agent 迭代

- 将人工原因映射到文字、人物、商品/Logo、几何、结构和构图指标；
- 修复“检测器误差压过高清视觉事实”和“完整但改版被误判”问题；
- 对Warp全局拉伸、Seam局部扭曲、Crop内容缺失分别建校准案例；
- Agent继续以Rule为锚点，只有可定位视觉证据支持时才覆盖；
- 建立Skill版本晋级和回退门槛，不在Validation上反向调参。

## P2：受控 AIGC

- 只对传统候选明确失败且允许第三方外发的Task调用；
- 保持每Task单次、预算上限、幂等和失败状态审计；
- 分开报告技术回图率、成功图A/B率、全计划分母A/B率和单个可用结果成本；
- 先解决文字、Logo和人物一致性，再决定是否扩大样本量。

## P3：工程化接入

- 冻结输入输出 JSON Schema 和错误码；
- 增加鉴权、任务队列、对象存储、审计与可观测性；
- Java先通过稳定Schema/进程或队列Adapter接入；
- 根据真实吞吐决定是否拆分CPU/GPU服务。

## 明确不做

- 不把商业素材上传Git或公开数据集；
- 不把自动Proxy或大模型建议称为人工准确率；
- 不为展示Agent作用而放松覆盖门禁；
- 不反复查看Validation并调参；
- 不覆盖已冻结Run或反复重试付费API；
- 不在接口未稳定时提前实现生产Java服务。
