# Movie60 Rule v3.3 阈值校准与人工证据报告

## 结论

`movie60@3.3.0` 是当前发布策略。它取消了按场景或算法名称直接加分的奖励，保留可解释的检测回归罚分与 C/D 门禁，并把等级阈值冻结为：

| 等级 | 可配置范围 |
|---|---:|
| A | `Quality >= 89` |
| B | `52 <= Quality < 89` |
| C | `42 <= Quality < 52` |
| D | `Quality < 42` |

最高分仍然是 100，但只有三个组成分本身达到满分时才可能得到 100。人物场景、`direct_warp`、`seam` 等不再因为名称获得额外分数。

## 评分公式

在三个组成分均存在时：

```text
Quality = 100 × (0.58 × 内容保真 + 0.32 × 视觉完整 + 0.10 × 构图)
```

通俗地说，分数首先回答“主要内容还在不在”，其次看“是否清晰、自然、没有明显结构破坏”，最后看“构图是否安全”。随后只应用两类负向证据：

1. 明确检测回归的透明罚分，例如关键文字回归、人脸未重检；
2. 明确语义或结构事故的等级上限，例如主要人物大幅缺失、关系丢失、海报主体/Logo 丢失。

阈值、权重、罚分和门禁均来自 `strategies/movie60/v3_3/scoring.yaml`，不写死在图片 ID 或业务代码中。

## 100 分饱和问题

旧 v3.2.2 在 420 个候选中有 68 个精确 100 分，全部属于人物场景；15 个物料存在多个候选同时 100 分。原因是基础分之后又叠加人物场景与方法奖励，超过 100 后被截断。

v3.3 对同一冻结 Run 重放后：

| 指标 | v3.2.2 | v3.3.0 |
|---|---:|---:|
| 候选数 | 420 | 420 |
| 精确 100 分 | 68 | **0** |
| 不同连续分数数量 | 未作为门禁 | **392** |
| 最低分 | — | 33.24 |
| 最高分 | 100.00 | **98.87** |
| 重新生成图片 | 否 | 否 |
| 重跑检测器 | 否 | 否 |

这说明 v3.3 修复了奖励导致的饱和，同时仍允许未来出现真实满分。

人工字段包括等级、理由、问题码、确认标记、评审者与时间戳。规范化摘要 SHA-256 为：

```text
67eafbaf967c9f8b1af9b65e7abc722f9a4d56e28460e092f9cdba613b116928
```

Release 构建器会在复制前后分别计算摘要；候选数、Task 数或任何人工字段变化都会让构建失败。机器 Rule、Agent 或大模型建议绝不能覆盖这些人工记录。

## 人工对齐结果

阈值仅在 84 个 development 候选上选择；42 个 proxy-holdout 人工候选不参与阈值搜索，只用于一次读出。这里仍是同一 Movie60 数据集内的保留组，不应表述为跨数据集泛化。

| 分区与策略 | 精确 A/B/C/D | A+B / C+D 二分类一致 | 人工 C/D 召回 | 机器 C/D 精确率 |
|---|---:|---:|---:|---:|
| development · v3.2.2 | 59.52% | 75.00% | 81.48% | 57.89% |
| development · **v3.3.0** | **66.67%** | **79.76%** | **81.48%** | **64.71%** |
| proxy-holdout · v3.2.2 | 54.76% | 76.19% | 75.00% | 75.00% |
| proxy-holdout · **v3.3.0** | **54.76%** | **76.19%** | 70.00% | **77.78%** |
| 全部 126 · v3.2.2 | 57.94% | 75.40% | 78.72% | 63.79% |
| 全部 126 · **v3.3.0** | **62.70%** | **78.57%** | 76.60% | **69.23%** |

选择 v3.3 的依据不是追求虚高的同集准确率，而是：消除错误加分饱和；development 指标改善；保留组的精确等级与 A+B/C+D 一致率不退化；C/D 召回下降 5 个百分点时，C/D 精确率上升 2.78 个百分点。后续新增独立人工标签后应创建 `v3_4`，不得原地改写本目录。
