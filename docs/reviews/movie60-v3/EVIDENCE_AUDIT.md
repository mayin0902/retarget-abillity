# Movie60 v3 证据审计

## 结论

本轮 420 条候选标签是**经人工粗审认可的大模型代理建议**，不是独立人工金标。
因此文档和 Release 只能报告“代理标签一致率”，不能写成“人工准确率”。

## 输入与边界

- 数据分母：60 个 Task × 7 个传统候选 = 420 个候选。
- 代理标签文件 SHA-256：
  `6841267a9fcb15a2bf0213b0c74d89d684983119bcf89613505efa7da1144df5`。
- 来源构成：294 条盲评建议、56 条同集校准建议、70 条回顾性 UI 补全建议。
- 每条代理标签均按 `task_id + method + image_sha256` 与冻结候选核对；不接受只按文件名匹配。
- `human_grade`、`human_reason` 和 `human_confirmed` 不参与本轮 v3 训练或选版。
- 旧 Run、v1、v2、v2.1 和备份中的 v3/v3.1 文件均不覆盖。

## 切分

切分见 `proxy-split-45dev-15holdout.json`。算法只读取 `task_id` 和
`scene_category`，按场景分层为 45 个开发 Task 和 15 个最终代理验证 Task；开发集再
分为 5 个诊断 fold。最终 15 个 Task 在 v3.2 冻结前不参与参数选择。

这里的“holdout”只表示策略开发过程中未用于选版，仍不等价于独立人工盲测。

## 可接受的结论

- 可以比较 v3、v3.1、v3.2 对同一代理标签的相对一致性。
- 可以用 C/D 召回检查高风险漏放趋势。
- 可以审计 Rule 分数、门禁、Agent 视觉证据和最终选择。
- 不可以据此声称真实线上准确率、独立人工一致率或跨数据集泛化能力。

后续真实结论仍需让人工在冻结的 15 个 Task（或新数据集）上独立评分，再另建报告，
绝不能回写本报告。
