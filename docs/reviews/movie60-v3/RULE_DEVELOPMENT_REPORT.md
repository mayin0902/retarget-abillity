# Movie60 Rule v3 开发集报告

## 选版结论

在冻结的 45 个开发 Task（315 个候选）上，v3.2 同时取得最高的 C/D 召回、A+B/C+D
一致率、精确等级一致率、macro-F1 和任务 Top1 命中率，因此冻结为本轮唯一胜出版本。
版本选择首先保护 C/D 漏放风险，再比较可用性一致率和整体等级表现。

| 版本 | 精确等级一致率 | A+B/C+D 一致率 | C/D 召回 | C/D 精确率 | Macro-F1 | Top1 命中* |
|---|---:|---:|---:|---:|---:|---:|
| v3 | 69.52% | 79.37% | 70.18% | 45.45% | 53.74% | 87.50% |
| v3.1 | 69.52% | 79.05% | 64.91% | 44.58% | 55.33% | 87.50% |
| **v3.2** | **73.97%** | **82.86%** | **87.72%** | **51.55%** | **64.97%** | **90.63%** |

\* Top1 只统计代理等级确实存在差异的 32 个 Task；全同级 Task 不计命中或失误。

## 三版差异

- v3：把旧评分中的部分 OCR/拉伸回归改为透明软惩罚，并引入主体严重缺失门禁。
- v3.1：增加场景条件和两名 Agent challenger 接口，避免只看七图缩略总览。
- v3.2：扩大 C/D 召回优先的门禁覆盖；Rule Top1 强制高清复核；Agent 可从完整七候选
  排名提出最多两名 challenger，每名都与 Rule Top1 做高清配对。

所有差异都在不可变 StrategyBundle 中声明，代码中没有 task ID、文件名或单图硬编码。
完整机器可解析结果见 `rule-development-results.json`。
